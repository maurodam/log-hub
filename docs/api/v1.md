# LogHub API v1

Base path: `/api/v1`. JSON is camelCase. Errors: `{"error": "..."}` (optional `"code"`).

## Authentication

Two ways to call the API:

| Client | Credential | CSRF |
|---|---|---|
| Browser (LogHub UI) | session cookie `loghub.session` (HttpOnly, Secure, SameSite=Strict) | required on POST/PUT/DELETE: send header `X-XSRF-TOKEN` with the value of the readable cookie `XSRF-TOKEN` (Angular `HttpClient` does it automatically for relative URLs) |
| Scripts, integrations | API key: `X-Api-Key` header (`?apiKey=` is accepted only by `/events/stream`, for `EventSource`) | not needed |

- `401 {"error"}`: not authenticated. `403 {"error"}`: missing permission.
- While `mustChangePassword` is true, every endpoint outside `/api/v1/auth/*` returns `403 {"error", "code": "password_change_required"}`.
- Permissions: `Ingest`, `Read`, `Write`, `Project`, `Organization`, `System`. Users get them from roles; API keys carry their own list.
- Nobody can grant or manage more than they have: roles, users and API keys with permissions the caller lacks return `403`.
- API responses carry `Cache-Control: no-store`.

### Auth endpoints

| Method | Path | Access | Body / result |
|---|---|---|---|
| GET | `/auth/providers` | anonymous | `{ local: true, oidc: { enabled: boolean, displayName: string \| null } }` |
| POST | `/auth/login` | anonymous, rate limited per IP (429) | `{ username, password }` → `200 CurrentUser`, `401` (same message for unknown user, wrong password and blocked sign-in) |
| POST | `/auth/logout` | session | `204` |
| GET | `/auth/me` | session or key | `200 CurrentUser` (also refreshes the `XSRF-TOKEN` cookie) |
| POST | `/auth/change-password` | session | `{ currentPassword, newPassword }` → `204`, `400 {error}` |
| GET | `/auth/oidc/login?returnUrl=/events` | anonymous, browser navigation | redirects to the identity provider (Microsoft Entra ID or any OpenID Connect provider); returns to `returnUrl` after login |

`CurrentUser = { id, username, displayName, email, permissions: string[], mustChangePassword: boolean, authProvider: "Local" | "Oidc" | "ApiKey" }`

Password rules: at least 12 characters. 5 failed logins for one account from one IP block that IP for 15 minutes (the owner can still sign in from elsewhere); 25 failures from any IP lock the account for 15 minutes. Sessions expire after 8 hours of inactivity and 7 days after sign-in.

## Shared types

`FilterSpec` (stored by signals and alerts; same meaning as the event query parameters):

```json
{ "text": "timeout", "levels": ["Error", "Fatal"], "properties": ["App=Billing"], "apiKeyIds": [3], "hasException": true, "traceId": null, "eventType": null }
```

All fields optional. `properties` entries are `Name=Value`; `42`, `true`, `null` and other JSON literals keep their type, `"42"` (quoted) is the string 42.

## Events (`Read`)

Query parameters shared by events and stats endpoints:

| Parameter | Meaning |
|---|---|
| `text` | case-insensitive contains on message or exception |
| `levels` | comma-separated: `Verbose,Debug,Information,Warning,Error,Fatal` |
| `from`, `to` | ISO 8601; `from` inclusive, `to` exclusive |
| `traceId` | exact |
| `eventType` | exact, as returned in `LogEvent.eventType` (`$A1B2C3D4`) |
| `property` | repeatable `Name=Value` |
| `apiKeys` | comma-separated API key ids: events ingested with any of these keys |
| `hasException` | `true` = only events with an exception |
| `signals` | comma-separated signal ids. Signals with the same `groupName` combine with OR; different groups (or no group) combine with AND |

| Method | Path | Result |
|---|---|---|
| GET | `/events?...&count=100&cursor=` | `{ events: LogEvent[], nextCursor: string \| null }`, newest first |
| GET | `/events/{id}` | `LogEvent` |
| GET | `/events/stream?...` | Server-Sent Events: `event: ping` at connect time and every 30 s, `event: log` (`id` = event id, `data` = LogEvent); resumes after `Last-Event-ID`; at most 5 open streams per user or key (`429`) |

`LogEvent = { id, timestamp, arrived, level, levelRank (0..5), messageTemplate, message, exception, eventType ("$A1B2C3D4"), traceId, spanId, apiKeyId: number | null, properties: object }`

## Stats (`Read`)

`GET /stats/overview?from=&to=&bucket=` plus the event filters. Defaults: last 24 hours, bucket chosen automatically (about 60 buckets; `bucket` in seconds overrides).

```json
{
  "from": "...", "to": "...", "bucketSeconds": 1800,
  "total": 1200, "errors": 12, "warnings": 40, "exceptions": 9, "distinctEventTypes": 37,
  "series": [ { "start": "...", "total": 30, "errors": 1, "warnings": 2 } ],
  "levels": [ { "level": "Error", "levelRank": 4, "count": 12 } ],
  "topEventTypes": [ { "eventType": "$A1B2C3D4", "messageTemplate": "...", "levelRank": 2, "count": 300 } ],
  "apiKeys": [ { "apiKeyId": 3, "title": "Billing", "count": 800 } ]
}
```

`series` has one entry per bucket (empty buckets have zeros). `levels` and `apiKeys` list only non-zero entries. `topEventTypes` and `apiKeys`: at most 10, highest count first.

## Signals

| Method | Path | Access | Body / result |
|---|---|---|---|
| GET | `/signals` | `Read` | `Signal[]`: shared signals plus the caller's own |
| POST | `/signals` | `Write` (`Project` when `isShared`) | `{ title, description, groupName, filter: FilterSpec, isShared }` → `201 Signal` |
| PUT | `/signals/{id}` | owner with `Write`, or `Project` for shared | same body → `Signal` |
| DELETE | `/signals/{id}` | same as PUT | `204`; protected signals → `400` |

`Signal = { id, title, description, groupName, filter: FilterSpec, isShared, isProtected, isOwn }`

Built-in shared signals: Errors (`Error, Fatal`, group `Level`), Warnings (`Warning`, group `Level`), Exceptions (`hasException`).

## Retention (`Project`)

| Method | Path | Body / result |
|---|---|---|
| GET | `/retention` | `RetentionPolicy[]` |
| POST | `/retention` | `{ signalId: number \| null, retentionDays, isEnabled }` → `201 RetentionPolicy` |
| PUT | `/retention/{id}` | same body → `RetentionPolicy` |
| DELETE | `/retention/{id}` | `204` |
| POST | `/retention/run` | `202`: runs the retention job now |
| GET | `/retention/storage` | `{ totalEvents, totalBytes, oldestEvent, partitions: [{ name, from, to, rows, bytes }] }` (row counts are estimates) |

`RetentionPolicy = { id, signalId, signalTitle, retentionDays, isEnabled, lastRunDate, lastDeletedCount, isManagedByEnvironment }`

When the environment variable `Retention__DefaultDays` is set, LogHub creates or updates the all-events policy at startup with that number of days; that policy has `isManagedByEnvironment: true` and PUT/DELETE on it return `409`.

`signalId = null` is the "all events" policy (at most one). The job runs every hour: whole daily partitions older than the all-events policy are dropped; signal policies delete matching older events in batches.

## Email notifications

### SMTP settings (`System`)

| Method | Path | Body / result |
|---|---|---|
| GET | `/settings/smtp` | `SmtpSettings` |
| PUT | `/settings/smtp` | `{ host, port, username, password (null = keep current), security, fromAddress, fromName, publicUrl }` → `SmtpSettings`; `409` when configured by environment |
| POST | `/settings/smtp/test` | `{ to }` → `204`, `502 {error}` when sending fails; 5 per minute per user (`429`) |

`SmtpSettings = { host, port, username, hasPassword, security: "None" | "StartTls" | "SslOnConnect", fromAddress, fromName, publicUrl, isConfigured, isFromEnvironment }`

The password is stored encrypted (ASP.NET Data Protection). Environment variables `Smtp__*` override the stored settings. `publicUrl` is the LogHub address used for links in emails.

### Alerts (`Read` to list, `Project` to change)

| Method | Path | Body / result |
|---|---|---|
| GET | `/alerts` | `Alert[]` |
| POST | `/alerts` | `AlertInput` → `201 Alert` |
| PUT | `/alerts/{id}` | `AlertInput` → `Alert` |
| DELETE | `/alerts/{id}` | `204` |
| POST | `/alerts/{id}/test` | `204`: sends a test email now; 5 per minute per user (`429`) |
| GET | `/alerts/{id}/notifications` | last 50 `Notification` |

`AlertInput = { title, description, signalId: number | null, filter: FilterSpec, threshold, windowMinutes, suppressionMinutes, recipients: string[], isEnabled }`
`Alert = AlertInput + { id, lastCheckedDate, lastTriggeredDate, lastError }`

With `Alerts__AllowedRecipientDomains` set (for example `contoso.com`), recipients outside those domains return `400`.
`Notification = { id, alertId, triggeredDate, eventCount, recipients: string[], status: "Sent" | "Failed", error }`

Every minute each enabled alert counts the events matching its signal and filter in the last `windowMinutes`. When the count is at least `threshold` and the last notification is older than `suppressionMinutes`, LogHub emails the recipients with up to 10 sample events and a link to the matching events.

## MCP (`Read`)

LogHub exposes a read-only Streamable HTTP MCP endpoint at `/mcp`. Authenticate with
`X-Api-Key: <key with Read permission>`. Session cookies and query-string keys do not
provide access. Missing or invalid keys return `401` JSON; keys without `Read` return `403`.

Available tools:

- `search_events`: filter by text, levels, time range, properties (`Name=Value`), source API key IDs,
  exception presence, trace ID, event type and shared signal IDs. Results are newest first.
  `count` defaults to 20 and is clamped to 1–100; pass `nextCursor` as `cursor` with the same filters
  for the next page. Messages are limited to 1,000 characters and exceptions to 2,000.
- `get_event`: look up an event by numeric ID. Message and exception are each limited to 16,000 characters.
- `get_stats_overview`: use the same filters, plus `bucketSeconds`, to query aggregates.
  The default time range is the last 24 hours, with at most 2,000 buckets.
- `list_signals`: list shared saved signals. API keys cannot access personal signals.

Timestamps use ISO 8601 with an offset. Truncated values end with `… [truncated N chars]`.
Properties are returned unchanged. Invalid filters, malformed cursors and missing events produce
MCP tool errors. Log contents are untrusted data and must not be treated as instructions.

The transport is stateless and needs no sticky sessions. Requests are limited per API key to
`Mcp:RequestsPerMinute` (default 120); excess requests return `429`. Each replica enforces its own
limit. Responses include `Cache-Control: no-store`.

Example Claude Code configuration:

```bash
claude mcp add --transport http loghub https://<host>/mcp --header "X-Api-Key: <key with Read>"
```

Custom connectors on claude.ai require OAuth, which LogHub does not currently implement.
